## :dart: O guia para alavancar a sua carreira

> Xamarin foi, por quase uma década, a principal forma de escrever apps Android e iOS em C# compartilhando código entre plataformas. Em 1º de maio de 2024 a Microsoft encerrou oficialmente o suporte ao Xamarin, substituindo-o pelo .NET MAUI — seu sucessor direto, mais rápido e mais integrado ao .NET moderno. Este guia serve dois públicos: quem ainda mantém um app Xamarin.Forms em produção e precisa de referência confiável, e quem está migrando (ou deveria migrar) esse app para o .NET MAUI. Reunimos documentação arquivada, guias oficiais de migração, cursos, ferramentas e uma trilha prática — tudo verificado e organizado para essa transição.

## ⚠️ Xamarin foi descontinuado

> **Xamarin chegou ao fim do suporte oficial da Microsoft em 1º de maio de 2024** — Xamarin.Forms, Xamarin.Android, Xamarin.iOS e Xamarin.Mac não recebem mais atualizações de segurança, correções de bugs ou suporte oficial. O [Visual Studio App Center](https://learn.microsoft.com/en-us/appcenter/), serviço de build e distribuição historicamente usado por apps Xamarin, também está sendo desativado pela Microsoft.

Isso não torna o conteúdo abaixo inútil — muito pelo contrário. Este guia foi reorganizado para servir dois objetivos concretos:

1. **Manutenção de apps legados** — se você ainda trabalha em um app Xamarin.Forms em produção, a documentação arquivada e as ferramentas listadas aqui continuam funcionando e são a referência mais confiável disponível.
2. **Migração para .NET MAUI** — o sucessor oficial e direto do Xamarin, mantido pela própria Microsoft dentro do .NET moderno (.NET 8, 9 e 10). A seção [🔄 Migração para .NET MAUI](#-migração-para-net-maui) reúne os guias oficiais passo a passo.

**Se você está começando um projeto novo, comece direto em .NET MAUI — não em Xamarin.**

## 🗺️ Roadmap

> Xamarin não tem mais um roadmap próprio — o caminho agora é a rota de saída para o .NET MAUI. As referências abaixo mostram o que veio depois e para onde o ecossistema está indo.

- [Xamarin support policy (Microsoft)](https://dotnet.microsoft.com/en-us/platform/support/policy/xamarin) — Página oficial que define a data de fim de suporte (1º de maio de 2024) e o que ela significa para cada produto Xamarin.
- [.NET MAUI — Novidades por versão](https://learn.microsoft.com/en-us/dotnet/maui/whats-new/) — Changelog oficial de cada versão do .NET MAUI (8, 9, 10…), o sucessor direto do Xamarin.Forms.
- [.NET MAUI Roadmap (GitHub Wiki)](https://github.com/dotnet/maui/wiki/Roadmap) — Prioridades e planejamento público do time do .NET MAUI.
- [Releases do dotnet/maui](https://github.com/dotnet/maui/releases) — Histórico completo de versões do .NET MAUI, com notas de cada release.

## 🔄 Migração para .NET MAUI

> A Microsoft não deixou o ecossistema Xamarin à própria sorte: existe um caminho de migração oficial, documentado e com ferramentas de apoio. Esta é a seção mais importante deste guia para quem mantém um app Xamarin hoje.

- [Visão geral: migrar do Xamarin para o .NET](https://learn.microsoft.com/en-us/dotnet/maui/migration/) — Página oficial que resume todos os caminhos de migração por tipo de projeto (Xamarin.Forms, Xamarin.Android, Xamarin.iOS, bibliotecas de binding).
- [Migrar projetos nativos Xamarin.Android, Xamarin.iOS e Xamarin.Mac para .NET](https://learn.microsoft.com/en-us/dotnet/maui/migration/native-projects) — Guia passo a passo para projetos que não usam Xamarin.Forms.
- [Migrar um app Xamarin.Forms para .NET MAUI (multi-projeto)](https://learn.microsoft.com/en-us/dotnet/maui/migration/multi-project-to-multi-project) — Mantém a estrutura de um projeto por plataforma, mais próxima do Xamarin.Forms original.
- [Migrar um app Xamarin.Forms para .NET MAUI (projeto único)](https://learn.microsoft.com/en-us/dotnet/maui/migration/multi-project-to-single-project) — Consolida tudo em um único `.csproj` multi-target, o formato recomendado para projetos novos.
- [Migração de projetos Xamarin.Forms UWP](https://learn.microsoft.com/en-us/dotnet/maui/migration/uwp-projects) — Caminho específico para quem tinha o alvo UWP (Windows) no Xamarin.Forms.
- [Migração de bibliotecas de binding Android](https://learn.microsoft.com/en-us/dotnet/maui/migration/android-binding-projects) — Para projetos que expõem SDKs nativos Android via binding.
- [Migração de bibliotecas de binding iOS](https://learn.microsoft.com/en-us/dotnet/maui/migration/ios-binding-projects) — Para projetos que expõem SDKs nativos iOS via binding.
- [Upgrade com o .NET Upgrade Assistant](https://learn.microsoft.com/en-us/dotnet/maui/migration/upgrade-assistant) — Ferramenta de linha de comando oficial que automatiza boa parte da conversão de um app Xamarin.Forms multi-projeto.
- [.NET Upgrade Assistant (repositório)](https://github.com/dotnet/upgrade-assistant) — Código-fonte da ferramenta oficial; instale via `dotnet tool install`.
- [.NET Upgrade Assistant — visão geral](https://learn.microsoft.com/en-us/dotnet/core/porting/upgrade-assistant-overview) — Documentação geral da ferramenta, incluindo cenários além da migração Xamarin.
- [Blog do Gerald Versluis (jfversluis.dev)](https://jfversluis.dev/) — Program Manager do .NET MAUI na Microsoft; publica guias práticos de migração e novidades de cada versão.
- [Blog do James Montemagno](https://montemagno.com/) — Principal Program Manager de mobile .NET na Microsoft; cobre migração, .NET MAUI e o ecossistema mobile do .NET.

## 🛠️ Ferramentas

> Ambiente e SDKs

- [Visual Studio](https://visualstudio.microsoft.com/vs/) — IDE oficial da Microsoft para Windows; o workload de Xamarin foi removido das versões mais recentes, restando o de .NET MAUI.
- [Extensão .NET MAUI para VS Code](https://marketplace.visualstudio.com/items?itemName=MS-DotNettools.dotnet-maui) — Suporte a .NET MAUI para quem prefere o VS Code no Windows, macOS ou Linux.
- [JetBrains Rider](https://www.jetbrains.com/rider/) — IDE multiplataforma com suporte completo a .NET MAUI (sucessor do Xamarin) em Windows, macOS e Linux.
- [Xamarin.Forms (NuGet, legado)](https://www.nuget.org/packages/Xamarin.Forms) — Pacote NuGet original do framework, ainda necessário para manter apps Xamarin.Forms em produção.
- [Microsoft.Maui.Controls (NuGet)](https://www.nuget.org/packages/Microsoft.Maui.Controls) — Pacote NuGet do .NET MAUI, sucessor direto do Xamarin.Forms.
- [Visual Studio App Center (docs)](https://learn.microsoft.com/en-us/appcenter/) — Serviço de build, teste e distribuição historicamente usado por apps Xamarin; a Microsoft está desativando o App Center — consulte o cronograma e as alternativas na própria documentação.

> Bibliotecas e toolkits (Xamarin e/ou .NET MAUI)

- [.NET MAUI Community Toolkit](https://github.com/CommunityToolkit/Maui) — Coleção de controles, comportamentos e helpers mantida pela comunidade e pela Microsoft, sucessora do Xamarin Community Toolkit.
- [.NET MAUI Community Toolkit — Markup](https://github.com/CommunityToolkit/Maui.Markup) — Permite escrever UI do .NET MAUI em C# fluente, sem XAML.
- [Xamarin Community Toolkit (arquivado)](https://github.com/xamarin/XamarinCommunityToolkit) — Repositório original do toolkit de controles para Xamarin.Forms, hoje arquivado — mantido apenas como referência.
- [CommunityToolkit.Mvvm](https://github.com/CommunityToolkit/dotnet) — Toolkit oficial de MVVM da Microsoft, usado tanto em apps Xamarin quanto .NET MAUI.
- [Prism Library](https://prismlibrary.com/) — Framework de MVVM e navegação para apps XAML, com suporte a Xamarin.Forms e .NET MAUI.
- [MvvmCross](https://github.com/MvvmCross/MvvmCross) — Framework de MVVM multiplataforma que também suporta Xamarin nativo e .NET MAUI.
- [ReactiveUI](https://www.reactiveui.net/) — Framework de MVVM reativo, usado tanto em apps Xamarin.Forms quanto .NET MAUI.
- [Refit](https://github.com/reactiveui/refit) — Biblioteca para consumir APIs REST de forma tipada, muito usada em apps Xamarin e .NET MAUI.
- [SkiaSharp](https://github.com/mono/SkiaSharp) — Biblioteca de renderização 2D usada para gráficos customizados em Xamarin.Forms e .NET MAUI.
- [Sharpnado.MaterialFrame](https://github.com/roubachof/Sharpnado.MaterialFrame) — Controle de efeito de vidro fosco (glassmorphism), compatível com Xamarin.Forms e .NET MAUI.
- [Shiny](https://github.com/shinyorg/shiny) — Framework para jobs em segundo plano, notificações push e sensores, com suporte a .NET MAUI (site: [shinylib.net](https://shinylib.net/)).

## 🤖 IA na prática

Migrar um app inteiro de Xamarin.Forms para .NET MAUI manualmente é um trabalho grande e repetitivo — exatamente o tipo de tarefa em que um assistente de IA ajuda de verdade, mas sob supervisão apertada.

**Para migrar (o caso de uso mais valioso aqui)**
- Rode primeiro o [.NET Upgrade Assistant](https://learn.microsoft.com/en-us/dotnet/maui/migration/upgrade-assistant) oficial — ele automatiza boa parte da conversão de projeto (`.csproj`, target frameworks, pacotes). A IA entra depois, na parte que a ferramenta não resolve sozinha.
- Cole um arquivo `.xaml` ou `.cs` que usa APIs do Xamarin.Forms (`Xamarin.Forms.Xaml`, `DependencyService`, `Xamarin.Essentials`) e peça para reescrever usando os namespaces equivalentes do .NET MAUI (`Microsoft.Maui.Controls`, `Microsoft.Maui.ApplicationModel`).
- Peça para **listar as APIs obsoletas ou removidas** usadas em um arquivo, comparando com os [guias oficiais de migração](#-migração-para-net-maui) antes de aceitar qualquer sugestão.
- Use [GitHub Copilot](https://github.com/features/copilot), [Claude Code](https://code.claude.com/docs/en/overview) ou [Cursor](https://cursor.com/) para automatizar a parte repetitiva: trocar `Xamarin.Forms` por `Microsoft.Maui.Controls` em vários arquivos, ajustar `using`s e resolver conflitos de namespace em lote.

**Para manter um app legado**
- Peça para explicar um trecho de código Xamarin.Forms antigo (comum ao herdar um projeto sem documentação) e sugerir correções compatíveis com a versão do Xamarin já em produção — sem "modernizar" para APIs que não existem mais no seu projeto.
- Cole um erro de build do Visual Studio, Xcode ou Android SDK e peça o diagnóstico: muitos erros em projetos Xamarin hoje vêm de versões de SDK do Android/iOS que avançaram e não são mais compatíveis com um projeto parado no tempo.

**Limites e boas práticas**
- IA erra bastante em Xamarin e .NET MAUI porque são tecnologias de nicho, com menos código de treino do que React ou Python — ela mistura APIs das duas plataformas com frequência. Sempre confira contra a documentação oficial.
- Nunca aceite uma migração em lote sem compilar e testar em dispositivo real (ou emulador) logo em seguida — comportamento de UI é a parte que mais quebra silenciosamente.
- Não cole código-fonte de apps proprietários em ferramentas de IA sem antes verificar a política de privacidade da sua empresa.
